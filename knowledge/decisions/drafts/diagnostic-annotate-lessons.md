## Why this exists

`diagnostic-498` designed the annotation schema and `exec-500` shipped the parser fix that unblocks it, so executable **#1 of 498's Q8 sequence — annotate `LESSONS.md` with `[status:]`/`[target:]`** — is the critical path. It cannot be authored yet, for three measured reasons:

1. ⚠️ **The detector that decides 250+ labels was never persisted.** 498 BUILT it, ran it over 282 proposals, reported 260 PASS / 22 UNDECIDABLE / 0 FAIL — and deposited only prose. An executable that re-derives the detector from that prose is re-running an unvalidated instrument on 250 irreversible-looking labels.
2. ⚠️ **Some entries carry TWO proposals with CONFLICTING statuses, and there is no rule for which one wins** — 498 never surfaced this because it counted PROPOSALS, not ENTRIES. Measured 2026-08-22: across all 370 entries the proposals-per-entry histogram is `{1: 362, 2: 8}`. ⚠️ **Of those 8, only 3 (ids 93, 116, 123) exist in today's `LESSONS.md`;** the other 5 (16, 17, 18, 20, 25) are old-format em-dash ORPHANS with no heading to annotate. **The 3 that matter each pair `stale` with `rejected`** — both on `PLANNER_TEMPLATE.md`, neither `implemented` — so none of them would be labelled `learned` in any case, and the live question is narrower than it first appears: does a `stale`+`rejected` pair make the entry pending, rejected, or `unknown`? 3. **The counts have drifted.** `LESSONS.md` is now **327** dated headings (498 measured 320) and **14** are unmatched in the corpus (498 measured 7). The corpus DB has not been re-ingested since 2026-08-19, so SESSION 58b's 4 appends and 58c's 3 are absent from it entirely.
